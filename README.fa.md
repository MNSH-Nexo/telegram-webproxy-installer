# Telegram WebProxy

> 🇮🇷 فارسی · 🇬🇧 [English](README.md)

نصب‌کننده‌ی یک‌مرحله‌ای و چندنمونه‌ای **وب‌پروکسی تلگرام** (MTProxy + Caddy) برای سرورهای Debian / Ubuntu، به‌همراه یک **پنل مدیریت تحت وب** که می‌تواند با **دامنه** یا با **آی‌پی سرور** گواهی HTTPS بگیرد. روش راه‌اندازی پنل مثل 3x-ui است.

## نصب

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MNSH-Nexo/telegram-webproxy-installer/main/panel.sh) install
```

این دستور **پنل وب** را نصب می‌کند (همان روش 3x-ui): پورت پنل را می‌پرسد، HTTPS پیشنهاد می‌دهد (Let's Encrypt برای دامنه یا آی‌پی سرور، یا گواهی خودت) و در پایان **نام کاربری، رمز و آدرس ورود را فقط یک‌بار** چاپ می‌کند؛ ذخیره‌شان کن. بعد از ورود به پنل، پروکسی‌ها را از **داشبورد ← نمونه‌ی جدید** بساز.

- پیش‌نیاز: `root` روی Debian 11/12 یا Ubuntu 20.04 به بالا (x86_64)، آزاد بودن پورت‌های `80` و `443`، و باز بودن پورت پنل در فایروال.
- اجرای دوباره‌ی همین دستور پنل را **به‌روز** می‌کند و تنظیمات، کاربرها و نمونه‌ها را نگه می‌دارد.
- بعد از نصب با دستور `dxwp` (منو، SSL، تنظیمات) مدیریتش کن.

---

- **نصاب پروکسی** (`install-tproxy.sh`): Go، Caddy، MTProxy و سرویس‌های systemd را نصب می‌کند. هر نمونه دامنه، پورت‌ها و پروفایل جدا و HTTPS خودکار دارد.
- **پنل وب** (`panel.sh`): نصب، فهرست، بررسی سلامت، تغییر نوع انتقال، ری‌استارت، حذف و پایش نمونه‌ها از مرورگر، پشت مسیر مخفی، ورود با رمز و گواهی Let's Encrypt.

## قابلیت‌ها

**پروکسی**

- **نصب با یک دستور**: Go، Caddy، MTProxy و سرویس‌ها خودکار نصب و تنظیم می‌شوند.
- **چندنمونه‌ای**: هر تعداد نمونه روی یک سرور؛ هر نمونه مستقل است (دامنه، پورت، پروفایل و سرویس جدا).
- **HTTPS خودکار**: گواهی Let's Encrypt برای هر نمونه را Caddy می‌گیرد و تمدید می‌کند.
- **سازگار با Cloudflare**: حالت `direct` یا `cf`.
- **نوع انتقال (carrier)**: `https`، `https-lanes`، `websocket`، `websocket-lanes`.
- **ماسک سایت**: نمایش یک سایت ایستا یا یک upstream محلی روی دامنه.
- **امن به‌صورت پیش‌فرض**: پورت‌های رله و MTProxy از اینترنت بسته هستند و ورودی عمومی فقط Caddy روی `443` است.
- **مقاوم و تکرارپذیر**: توقف روی هر خطا، تلاش مجدد دانلود، بررسی دیسک و معماری، اجرای دوباره‌ی امن.

**پنل وب**

- **داشبورد**: نصب نمونه‌ی جدید با فرم (دامنه، حالت، نوع انتقال، ایمیل، سکرت، ماسک سایت، گزینه‌های پیشرفته) و لاگ زنده؛ فهرست، بررسی سلامت، کپی لینک تلگرام، تغییر نوع انتقال، ری‌استارت، حذف و حذف همه.
- **بررسی پیش از نصب**: قبل از هر نصب، پنل دامنه را resolve می‌کند و جلوی نصب را می‌گیرد اگر دامنه رکورد DNS ندارد، به آی‌پی دیگری اشاره می‌کند، یا پروکسی کلودفلر روشن است (آی‌پی‌های کلودفلر). مواردی مثل چند آی‌پی یا رکورد IPv6 هشدار می‌دهند و می‌توانید ادامه دهید.
- **بررسی بعد از نصب (کلودفلر)**: در حالت cf، پس از پایان نصب وضعیت DNS دوباره خوانده می‌شود. اگر پروکسی هنوز روشن نشده باشد، پایین صفحه پیام «پروکسی را روشن کنید» با دکمه‌ی «بررسی دوباره» نمایش داده می‌شود. خطاها و پیام‌های بررسی همیشه در کارت پایین صفحه می‌آیند.
- **صفحه‌ی SSL**: گرفتن گواهی Let's Encrypt برای خود پنل با **دامنه** یا **آی‌پی سرور**، یا استفاده از فایل گواهی خودت؛ نمایش وضعیت و تاریخ انقضا.
- **صفحه‌ی پنل**: تغییر نام کاربری، رمز، پورت و مسیر مخفی؛ کپی آدرس پنل؛ خروج.
- **صفحه‌ی ترافیک**: اتصال‌های زنده و حجم آپلود / دانلود هر نمونه.
- **فارسی و انگلیسی**، تم روشن / تیره / خودکار و چند پالت رنگی.
- **امنیت**: اطلاعات ورود تصادفی، مسیر مخفی، رمز با PBKDF2-SHA256، کوکی `HttpOnly` و `SameSite=Strict`، قفل ۵ دقیقه‌ای بعد از ۵ ورود اشتباه، و بدون اجرای shell برای آرگومان‌های نصاب.
- **سایت پوششی رندوم**: اگر سایت دلخواه ندهی، برای هر دامنه یک سایت واقعی‌نما به‌صورت رندوم ساخته می‌شود (۳ قالب در پوشه‌ی `sites/` با نام برند، رنگ و ایمیل اختصاصی هر دامنه، صفحه‌های داخلی و صفحه‌ی ۴۰۴). با `--site-template edgewire|cdncrest|tesla|plain` می‌توان یکی را اجباری کرد. تعداد ورکر پیش‌فرض MTProxy برابر ۱۰ است.
- **بررسی خودکار به‌روزرسانی**: هر بار که پنل باز می‌شود، نسخه‌ی مخزن را بررسی می‌کند؛ فقط اگر نسخه‌ی جدیدتری باشد، در گوشه‌ی بالای صفحه‌ی تنظیمات دکمه‌ی «به‌روزرسانی» ظاهر می‌شود (تنظیمات، کاربرها و نمونه‌ها حفظ می‌شوند).
- **مدیریت به سبک 3x-ui**: دستور `dxwp` منو و CLI برای تنظیمات و SSL (گرفتن، ابطال، تمدید، فهرست).
- **بدون وابستگی اضافه**: پنل فقط یک فایل پایتون ۳ است (کتابخانه‌ی استاندارد).

## پیش‌نیازها

| مورد | مقدار |
| ---- | ----- |
| سیستم‌عامل | Debian 11/12 یا Ubuntu 20.04 به بالا (systemd + apt) |
| معماری | x86_64 / amd64 |
| کاربر | `root` |
| پورت‌های آزاد | `80` و `443` (برای Caddy)، به‌علاوه‌ی یک پورت برای پنل |

## پنل وب

### قبل از نصب

| بررسی | دلیل |
| ----- | ---- |
| اجرا با `root` روی Debian / Ubuntu | نصاب از `apt` و `systemd` استفاده می‌کند |
| پورت **80** از اینترنت در دسترس باشد | Let's Encrypt گواهی دامنه و آی‌پی را روی پورت ۸۰ تأیید می‌کند |
| **پورت پنل** در فایروال / گروه امنیتی سرویس‌دهنده باز باشد | پنل در `https://HOST:PORT/PATH/` باز می‌شود (پورت تصادفی است مگر خودت انتخاب کنی) |
| برای گواهی **دامنه**: رکورد `A` به این سرور اشاره کند | بدون آن تأیید دامنه شکست می‌خورد |
| اگر دامنه در Cloudflare است: رکورد روی **DNS only** (ابر خاکستری) باشد | وگرنه Cloudflare به درخواست تأیید جواب می‌دهد |

### نصب

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MNSH-Nexo/telegram-webproxy-installer/main/panel.sh) install
```

مراحل مثل 3x-ui است:

1. وابستگی‌ها (`python3`، `curl`، `openssl`، `socat`، `cron`) و سرویس `dxwp-panel` نصب می‌شوند.
2. **نام کاربری**، **رمز** و **مسیر مخفی** تصادفی ساخته می‌شود.
3. می‌پرسد «پورت پنل را دلخواه می‌خواهی؟» (`y` برای انتخاب پورت، `n` برای پورت تصادفی).
4. **منوی SSL** نمایش داده می‌شود (پایین‌تر).
5. اطلاعات ورود و آدرس دسترسی **فقط یک‌بار** چاپ می‌شود؛ ذخیره‌شان کن (رمز فقط به‌صورت هش نگه‌داری می‌شود).

```
Username:    f81H93SEuU
Password:    L9U0XCnADp
Port:        18321
WebBasePath: 1DrN2xzMfq0tNQi20V
Access URL:  https://203.0.113.10:18321/1DrN2xzMfq0tNQi20V/
```

> بدون HTTPS رمز ورود به‌صورت متن ساده ارسال می‌شود؛ مگر پشت تونل یا ریورس‌پروکسی هستی، یکی از سه گزینه‌ی اول SSL را انتخاب کن.

### گزینه‌های SSL: دامنه، آی‌پی سرور یا گواهی خودت

```
1. Let's Encrypt for a domain (90 days, auto-renews)
2. Let's Encrypt for this server's IP (~6 days, auto-renews)      <- پیش‌فرض
3. Custom certificate (paths to existing files)
4. Skip (plain HTTP)
```

#### گزینه ۱: با دامنه (پیشنهادی)

1. یک رکورد `A` بساز، مثلاً `panel.example.com ← آی‌پی سرور` (در Cloudflare: **DNS only**).
2. گزینه‌ی `1` را بزن و دامنه را وارد کن. نصاب با `acme.sh` گواهی می‌گیرد و روی پنل اعمال می‌کند.
3. `https://panel.example.com:<پورت>/<مسیر>/` را باز کن.

گواهی ۹۰ روز اعتبار دارد و خودکار تمدید می‌شود. همین دامنه را می‌شود برای یک نمونه‌ی پروکسی هم استفاده کرد؛ پنل روی پورت جدا گوش می‌دهد، نه `443`.

#### گزینه ۲: با آی‌پی سرور (بدون دامنه)

1. گزینه‌ی `2` را بزن. آی‌پی عمومی تشخیص داده می‌شود و می‌توانی تأیید یا عوض کنی؛ آدرس IPv6 هم می‌شود اضافه کرد.
2. یک **گواهی آی‌پی** Let's Encrypt (پروفایل کوتاه‌مدت، حدود ۶ روز) گرفته و خودکار تمدید می‌شود.
3. `https://<آی‌پی سرور>:<پورت>/<مسیر>/` را باز کن.

> گواهی آی‌پی کوتاه‌مدت است و زیاد تمدید می‌شود. اگر دامنه داری، دامنه بهتر است.

#### گزینه ۳: گواهی خودت

مسیر کامل `fullchain.pem` و `privkey.pem` را بده. وقتی فایل عوض شود پنل خودش دوباره می‌خواندش.

#### گزینه ۴: رد کردن

پنل روی HTTP ساده بالا می‌آید. فقط پشت تونل یا ریورس‌پروکسی استفاده کن، مثلاً با SSH:

```bash
ssh -L 8443:127.0.0.1:<پورت-پنل> root@<سرور>
# بعد باز کن: http://127.0.0.1:8443/<مسیر>/
```

#### Caddy و پورت ۸۰

Caddy (دروازه‌ی پروکسی) پورت ۸۰ را در اختیار دارد. هنگام گرفتن و هر بار تمدید گواهی، `acme.sh` **چند ثانیه Caddy را متوقف می‌کند**، روی پورت ۸۰ تأیید می‌گیرد و دوباره روشنش می‌کند (با pre / post hook). در آن لحظه پروکسی روی `443` کوتاه‌مدت در دسترس نیست. گواهی دامنه تقریباً هر ۶۰ روز تمدید می‌شود و گواهی آی‌پی خیلی بیشتر.

### کار با پنل

آدرس دسترسی را باز کن و وارد شو. نوار پایین چهار صفحه دارد:

| صفحه | کار |
| ---- | --- |
| **داشبورد** | نصب نمونه‌ی پروکسی با فرم (حین نصب لاگ زنده دیده می‌شود)؛ فهرست، بررسی سلامت، کپی لینک تلگرام، تغییر نوع انتقال، ری‌استارت یا حذف نمونه؛ حذف همه. |
| **SSL** | گرفتن گواهی پنل با دامنه یا آی‌پی، یا فایل دستی؛ وضعیت و انقضا؛ خاموش کردن HTTPS. بعد از تغییر، پنل ری‌استارت می‌شود و به آدرس جدید می‌روی. |
| **پنل** | تغییر نام کاربری، رمز، پورت و مسیر مخفی (دکمه‌ی کلید یک مسیر تصادفی می‌سازد)؛ کپی آدرس؛ خروج. |
| **ترافیک** | اتصال‌های زنده و بایت‌های آپلود / دانلود هر نمونه، با مجموع. |

نکته‌ها:

- **نمونه‌ی Cloudflare**: در حالت `cf` پیش از زدن «نصب» پروکسی Cloudflare را **خاموش** کن و بعد از نصب روشن. پنل هیچ‌وقت منتظر فشردن کلید نمی‌ماند.
- **تغییر نوع انتقال** فقط پروفایل نمونه را ویرایش و رله را ری‌استارت می‌کند؛ پورت‌ها، سکرت و ماسک سایت دست نمی‌خورند.
- هر لحظه فقط یک عملیات نصب / حذف همه اجرا می‌شود.

### دستور `dxwp`

بعد از نصب، دستور `dxwp` پنل را از شل سرور مدیریت می‌کند. بدون آرگومان منو باز می‌شود:

| دستور | توضیح |
| ----- | ----- |
| `dxwp` | منوی تعاملی |
| `dxwp show` | نمایش آدرس پنل، نام کاربری و وضعیت SSL |
| `dxwp ssl` | منوی SSL (دامنه / آی‌پی / دستی / رد) |
| `dxwp ssl-domain example.com` | گواهی برای دامنه |
| `dxwp ssl-ip 203.0.113.10 [IPv6]` | گواهی برای آی‌پی |
| `dxwp ssl-custom CERT KEY` | استفاده از فایل‌های گواهی موجود |
| `dxwp ssl-list` | فهرست گواهی‌ها |
| `dxwp ssl-renew NAME` | تمدید اجباری گواهی |
| `dxwp ssl-revoke NAME` | ابطال و حذف گواهی |
| `dxwp setting -username U -password P -port N -webBasePath PATH` | تغییر تنظیمات |
| `dxwp setting -reset` | بازنشانی نام کاربری، رمز، پورت و مسیر به مقادیر تصادفی |
| `dxwp start` / `stop` / `restart` / `status` / `log` | کنترل سرویس |
| `dxwp install` | به‌روزرسانی فایل‌های پنل با حفظ تنظیمات |
| `dxwp uninstall` | حذف پنل (نمونه‌ها و گواهی‌ها می‌مانند) |

نصب خودکار: `DXWP_NONINTERACTIVE=1 DXWP_SSL_MODE=ip bash panel.sh install` (حالت `domain` با `DXWP_SSL_DOMAIN`، حالت `custom` با `DXWP_SSL_CERT` و `DXWP_SSL_KEY`؛ اختیاری: `DXWP_USERNAME`، `DXWP_PASSWORD`، `DXWP_PANEL_PORT`، `DXWP_WEB_BASE_PATH`).

### عیب‌یابی پنل

- **گرفتن گواهی شکست می‌خورد**: بررسی کن دامنه به این سرور اشاره کند، پورت ۸۰ باز باشد (فایروال سرویس‌دهنده / `ufw`)، چیز دیگری روی پورت ۸۰ گوش ندهد و رکورد Cloudflare روی DNS only باشد؛ بعد دوباره `dxwp ssl`.
- **پنل باز نمی‌شود**: پورت پنل را در فایروال باز کن؛ `dxwp status` و `dxwp log` را ببین؛ آدرس باید مسیر مخفی را با `/` آخرش داشته باشد.
- **رمز یا مسیر را فراموش کردی**: `dxwp setting -reset` (مقادیر تصادفی) یا `dxwp setting -password NEW`.
- **هشدار گواهی در مرورگر**: روی HTTP ساده هستی یا گواهی منقضی شده؛ `dxwp ssl` یا `dxwp ssl-renew NAME`.
- **بعد از ورودهای اشتباه قفل شدی**: ۵ دقیقه صبر کن.

### نکات امنیتی

مسیر مخفی را فاش نکن، از HTTPS استفاده کن و در صورت امکان دسترسی به پورت پنل را در فایروال به آی‌پی خودت محدود کن. رمزها با PBKDF2-SHA256 هش می‌شوند و بعد از ۵ ورود اشتباه، آی‌پی ۵ دقیقه قفل می‌شود.

## نوع انتقال (carrier)

> **نوع انتقال مجاز برای هر حالت:** حالت `direct` فقط `https` یا `https-lanes`؛ حالت `cf` (پشت پروکسی کلودفلر) فقط `websocket` یا `websocket-lanes`. پنل فقط همان دو گزینه را فعال می‌کند و نصاب ترکیب‌های دیگر را رد می‌کند.

| حالت | پوسته | اتصال | مناسب برای |
| ---- | ----- | ----- | ---------- |
| `https` | HTTPS | تکی | حالت direct؛ ساده‌ترین و کم‌سربارترین |
| `https-lanes` | HTTPS | موازی | حالت direct وقتی سرعت بیشتر می‌خواهی |
| `websocket` | WebSocket | تکی | پشت Cloudflare یا ریورس‌پروکسی؛ شبیه ترافیک وب عادی |
| `websocket-lanes` | WebSocket | موازی | پشت Cloudflare و سرعت بیشتر |

**پیشنهاد:** پشت Cloudflare از `websocket-lanes` و برای حالت direct از `https` یا `https-lanes` استفاده کن. نوع انتقال را بعداً از پنل (**داشبورد ← تغییر نوع**) یا با اجرای دوباره‌ی نصاب با همان دامنه می‌شود عوض کرد.

## راه‌اندازی Cloudflare

1. رکورد زیردامنه را در Cloudflare روی **DNS only** (ابر خاکستری) بگذار، **پیش از نصب**.
2. نصاب را با حالت `cf` اجرا کن تا گواهی Let's Encrypt را با پروکسی خاموش بگیرد.
3. بعد از پایان نصب رکورد را روی **Proxied** (ابر نارنجی) بگذار.

توکن API لازم نیست.

## دستورات CLI نصاب

```bash
# نمونه‌ی direct
bash install-tproxy.sh --hostname proxy.example.com --mode direct --carrier https-lanes --email admin@example.com

# نمونه‌ی Cloudflare (پیش از نصب پروکسی را خاموش و بعد از نصب روشن کن)
bash install-tproxy.sh --hostname cdn.example.com --mode cf

bash install-tproxy.sh --list     # فهرست نمونه‌ها
bash install-tproxy.sh --verify   # سلامت همه‌ی نمونه‌ها
bash install-tproxy.sh --wipe     # حذف همه چیز
```

فهرست کامل گزینه‌ها در [README انگلیسی](README.md#cli-usage) آمده است.

## حذف

- فهرست نمونه‌ها: `bash install-tproxy.sh --list`
- حذف یک نمونه: پنل ← **داشبورد ← حذف**
- حذف همه‌ی نمونه‌ها و اجزای مشترک: `bash install-tproxy.sh --wipe`
- حذف فقط پنل: `dxwp uninstall` (نمونه‌ها و گواهی‌ها می‌مانند)

## عیب‌یابی

- **نصب با پیام خطا متوقف می‌شود**: اسکریپت روی هر دستور ناموفق می‌ایستد؛ خطا و فایل لاگ اشاره‌شده را بخوان.
- **مبدأ HTTPS هنوز آماده نیست**: DNS هنوز پخش نشده یا پروکسی Cloudflare هنوز خاموش است؛ چند دقیقه صبر کن و دوباره بررسی کن.
- **پورت 443 اشغال است**: چیز دیگری روی آن گوش می‌دهد؛ قبل از نصب آزادش کن.

## کاربران، اینباندها و ترافیک لحظه‌ای

- **اینباند = نمونه** (دامنه + نوع انتقال که در داشبورد ساخته می‌شود). **کاربران** جدا هستند: هر کاربر سکرت مخصوص خودش را دارد و به یک یا چند اینباند وصل می‌شود.
- برای هر (کاربر، اینباند) پنل یک پروفایل با سکرت کاربر به `profiles.json` همان نمونه اضافه می‌کند و یک MTProxy اختصاصی (`mtproxy@dxu-<port>`) روی پورت لوپ‌بک خودش بالا می‌آورد؛ همین باعث می‌شود ترافیک و سقف هر کاربر جدا حساب شود.
- ترافیک با شمارنده‌های nftables روی همان پورت‌ها شمرده می‌شود (جدول `inet dxwp_acct`) و **هر ثانیه** خوانده می‌شود. کاربران، صفحه‌ی وضعیت (CPU، رم، سواپ، دیسک و سرعت کلی) و شمارنده‌های داشبورد هر ۱ تا ۳ ثانیه خودشان به‌روز می‌شوند.
- کاربری که به سقف حجم یا تاریخ انقضا برسد یا غیرفعال شود، بک‌اندش خودکار متوقف می‌شود.
- منوی سرور و پنل وب یک تنظیم مشترک دارند: `dxwp setting ...`، منو و صفحه‌ی تنظیمات پنل همه `/etc/dxwp-panel/config.json` را می‌نویسند و `install-result.env` را هماهنگ نگه می‌دارند.
- گواهی: صفحه‌ی وب فقط دامنه یا IP را می‌گیرد (IPv4 سرور از قبل پر است). هر سرویسی که پورت ۸۰ را گرفته باشد برای درخواست متوقف و بعدش دوباره روشن می‌شود و لاگ درخواست زیر دکمه نمایش داده می‌شود.

## سرویس ساب (Subscription)

- پنل > **تنظیمات > تنظیمات ساب** (بین تنظیمات پنل و ظاهر): فعال‌سازی، آی‌پی، دامنه، پورت (پیش‌فرض ۲۰۹۶)، مسیر URI (`/sub/`) و مسیر پراکسی معکوس (اختیاری). فیلدها مثل 3x-ui هستند.
- آدرس ساب هر کاربر = `<آدرس پایه><سکرت کاربر>`. اپ‌ها لیست base64 لینک‌های همان کاربر را می‌گیرند (با هدر `Subscription-Userinfo` برای مصرف، سقف و انقضا) و مرورگر صفحه‌ی ساب DX را.
- کاربران > بارکد: ردیف اول کپی لینک ساب، بعد کپی همه‌ی پروکسی‌ها، بعد برای هر اینباند یک بخش بازشونده با دکمه‌ی کپی لینک، ذخیره‌ی تصویر و بارکد.
- پورتِ مشغول رد می‌شود و تنظیمات قبلی می‌ماند. با CLI: `dxwp setting -subEnable on -subPort 2096 -subPath /sub/`.

- `dxwp doctor` وضعیت Caddy، هر اینباند (رله، MTProxy، DNS) و هر کاربر (پروفایل + بک‌اند) را چک می‌کند و می‌گوید چه چیزی را درست کنی.
